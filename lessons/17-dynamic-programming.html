Dynamic programming

Dynamic programming (DP) has a scary name for a simple idea: don't solve the same sub-problem twice — write the answer down. It turns exponential recursion into polynomial time. The hard part is not the code, it's defining what a sub-problem is. This lesson gives you a 5-step recipe and lets you watch tables fill up.

1. 👀 The problem with plain recursion

Go back to lesson 10's fib(5) call tree: fib(3) was computed twice, fib(2) three times. Now watch the same function with a dict called memo. When an answer is already in the memo, the call returns immediately — whole branches of the tree disappear.

Without memo: fib(n) makes about 2ⁿ calls. With memo: each fib(k) is computed once → O(n). fib(100) goes from "longer than the universe" to instant.

from functools import cache

@cache                      # Python's built-in memoization
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(100))

2. Top-down and bottom-up

Top-down (memoization)

Write the natural recursion, add a memo (or @cache). Start from the big question; the recursion asks the small ones. Easiest to write. Watch the recursion depth (~1000 in Python).

Bottom-up (tabulation)

Fill a list/table from the smallest sub-problems up to the big one, with a loop. No recursion, and often you only need the last row → less memory.

3. The 5-step recipe

🧩 How to build any DP solution
  1. State — say in words what dp[i] (or dp[i][j]) means. "dp[a] = the fewest coins that make amount a."
  2. Recurrence — how is dp[i] built from smaller states? Think about the last decision: "the last coin was some c, so dp[a] = 1 + dp[a − c] for the best c."
  3. Base cases — the smallest states you know directly. "dp[0] = 0."
  4. Order — fill states so that everything a state needs is already computed (usually small → big).
  5. Answer — which cell is the answer? dp[amount], or max(dp), or dp[n][m]…

Signals: "how many ways", "minimum / maximum cost / profit", "can you reach / make / partition…", "longest / shortest subsequence", a choice at every step whose effect continues later. If greedy fails on a small example, think DP.

4. 👀 1-D DP: coin change

For every amount from 1 up, try every coin as the "last coin" and keep the best. The blue cell is the smaller amount we build on.

5. 👀 2-D DP: two strings

With two strings, the state is "the answer for the first i characters of a and the first j characters of b". Each cell looks at its neighbours up, left and diagonal (blue).

8. 📌 Summary

  • DP = recursion without repeated work. Memo (top-down) or table (bottom-up).
  • Recipe: state → recurrence (think about the last decision) → base cases → order → answer.
  • Time ≈ number of states × work per state.
  • Learn the families; most problems are a member of one.
