Lesson 05 · Core pattern

Two pointers

Your first real pattern. Two index variables walk through a list, and every step they throw away part of the problem. It turns many O(n²) "try every pair" solutions into O(n).

🎯 After this lesson you can
  • recognise when a problem wants two pointers (the "signals")
  • write the two templates — opposite ends and fast & slow — from memory
  • explain why it is correct (not just copy it)
  • solve LeetCode 125, 167, 283, 26, 977, 11, 15

1. The real-life picture

You and a friend stand at the two ends of a line of people sorted by height. You want two people whose heights add up to exactly 340 cm. You call out the sum of the two people you are standing next to:

  • too small? The shortest person can't work with anyone — even the tallest person wasn't enough. So you step to the next person.
  • too big? The tallest person can't work with anyone — even the shortest person was too much. Your friend steps inwards.

Every step, one person is removed forever. With n people you need at most n steps — not n × n.

Why is it correct? (the part most tutorials skip)

Say nums[left] + nums[right] < target. nums[right] is the biggest number still alive. If nums[left] plus the biggest number is still too small, then nums[left] plus any other alive number is also too small. So nums[left] is useless → left += 1 loses nothing. The "too big" case is the mirror image.

This is called an invariant: "if an answer exists, it is inside [left, right]". It is true at the start and stays true after every step. When you can say the invariant, you can write the loop without bugs.

4. Template A — opposite ends

🧩 Template: opposite ends 
left, right = 0, len(arr) - 1
while left < right:
    # look at arr[left] and arr[right]
    if found_answer:
        return ...
    elif need_bigger:      # (only works if arr is sorted)
        left += 1
    else:
        right -= 1

Signals: sorted list · "pair" / "two numbers" · palindrome · reverse in place · "from both ends" · container / area between two lines.

The same shape reverses a list: swap the two ends, then move both inwards.

Dart
var l = 0, r = chars.length - 1;
while (l < r) {
  final tmp = chars[l];
  chars[l] = chars[r];
  chars[r] = tmp;
  l++; r--;
}
Python
left, right = 0, len(chars) - 1
while left < right:
    chars[left], chars[right] = chars[right], chars[left]
    left += 1
    right -= 1
Dart → Python Python has no ++/--: write left += 1. And a, b = b, a swaps two values in one line (Python builds the right side first, then assigns) — no tmp variable needed.

5. Template B — fast & slow (same direction)

Both pointers go left → right. read (fast) looks at every element. write (slow) only moves when we keep something. Everything before write (green) is the finished answer — that's the invariant.

🧩 Template: fast & slow (in-place filter) 
write = 0
for read in range(len(arr)):
    if keep(arr[read]):
        arr[write] = arr[read]
        write += 1
# arr[:write] is the answer

Signals: "in place" · "without extra memory" · remove / move / keep some elements · "keep the relative order".

6. Common mistakes

MistakeFix
while left <= right in pair problemsThen left == right uses the same element twice. Use <.
Forgetting to move a pointer in some branchInfinite loop. Every path through the loop body must move at least one pointer.
Using opposite ends on an unsorted listSort first (if indexes don't matter) or use a dict (lesson 04).
right = len(arr)Last index is len(arr) - 1. arr[len(arr)] → IndexError.

8. 📌 Summary

  • Opposite ends: sorted list, pairs, palindromes, reversing. Each step removes one element from the search.
  • Fast & slow: in-place filtering. write marks the end of the finished part.
  • Both are O(n) time, O(1) extra space.
  • To be sure it's correct, say the invariant.
