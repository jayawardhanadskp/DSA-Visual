Linked lists

A linked list is a chain of small objects ("nodes"), each holding a value and an arrow to the next node. There are no indexes. Linked-list problems aren't hard algorithms — they test whether you can move arrows without losing anything. The trick is to draw.

1. The node

Dart
class ListNode {
  int val;
  ListNode? next;
  ListNode(this.val, [this.next]);
}
Python (LeetCode's version)
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

A variable like head or curr doesn't hold a node — it points to one (lesson 01, references!). So curr = curr.next moves a pointer; it doesn't change the list. Only assignments to .next change the list.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

head = ListNode(1, ListNode(2, ListNode(3)))
curr = head
while curr is not None:          # the standard walk
    print(curr.val, "->", end=" ")
    curr = curr.next
print("None")

insert / delete after a node you holdO(n)O(1) — re-point arrows

3. 👀 Reversing a list

Walk once and flip every arrow to point backwards. You need three pointers: prev (the part already reversed), curr (the node being flipped) and nxt (so you don't lose the rest). Step through slowly — and draw it on paper too.

4. 👀 Fast & slow pointers

Two pointers start at the head; fast moves 2 steps for every 1 step of slow. When fast reaches the end, slow is in the middle.

And if the list has a cycle, fast never reaches the end — it goes around and eventually lands on the same node as slow (like a fast runner lapping a slow one on a track).

5. 👀 The dummy node

When you build a new list (merge, add, filter), the first node is a special case: "is the result empty yet?". A dummy node removes that case. Start with a fake node, always attach to tail.next, and return dummy.next.

🧩 Linked list templates 
# walk
curr = head
while curr:
    ...
    curr = curr.next

# reverse
prev, curr = None, head
while curr:
    nxt = curr.next
    curr.next = prev
    prev, curr = curr, nxt
# prev is the new head

# fast & slow
slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next

6. How to never get lost

  1. Draw 3–4 boxes and arrows. Do every assignment with an eraser.
  2. Before changing x.next, ask: "Do I still have a pointer to the node x.next points to now?" If not, save it first.
  3. Check the edge cases: empty list (head is None), one node, two nodes.
  4. Guard every .next access: x.next.next crashes if x.next is None (AttributeError: 'NoneType' object has no attribute 'next').
