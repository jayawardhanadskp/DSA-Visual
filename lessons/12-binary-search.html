Binary search

Every step throws away half of what's left. A billion sorted numbers need only 30 steps. The idea is simple — the difficulty is the details (< or <=? mid or mid - 1?). This lesson gives you templates you can trust, and shows the powerful "binary search on the answer".

🎯 After this lesson you can
  • write the classic search and the lower-bound search without off-by-one bugs
  • use binary search on things that aren't sorted lists (slopes, rotations, answers)
  • solve LeetCode 704, 35, 69, 34, 162, 153, 33, 875, 74

1. Play it first

The best strategy is always to guess the middle of what's left. "Too small" removes the whole lower half at once. That's binary search.

2. 👀 The classic version

🧩 Template A — find an exact value 
lo, hi = 0, len(nums) - 1
while lo <= hi:                 # search space nums[lo..hi] is not empty
    mid = (lo + hi) // 2
    if nums[mid] == target:
        return mid
    if nums[mid] < target:
        lo = mid + 1            # mid is checked → exclude it
    else:
        hi = mid - 1
return -1

3. 👀 Lower bound: the first position that is big enough

Many problems don't ask "is it there?" but "where does it start?" or "where would it go?". This template finds the first index where a condition becomes true. With duplicates it finds the first one.

🧩 Template B — first index where condition(i) is True 
lo, hi = 0, len(nums)           # hi = len: "maybe nothing qualifies"
while lo < hi:
    mid = (lo + hi) // 2
    if condition(mid):          # e.g. nums[mid] >= target
        hi = mid                # mid might be the answer → keep it
    else:
        lo = mid + 1
return lo                       # lo == hi == the first True (or len)

Python has it built in: bisect.bisect_left(nums, x) (first index with value ≥ x) and bisect_right (first index with value > x).

import bisect
nums = [1, 3, 3, 3, 5, 8]
print(bisect.bisect_left(nums, 3), bisect.bisect_right(nums, 3))   # 1 4
print(bisect.bisect_left(nums, 4))      # 4: where 4 would be inserted
bisect.insort(nums, 4)                  # insert and keep it sorted
print(nums)

4. The big idea: binary search on a yes/no question

Binary search doesn't really need a sorted list. It needs a question whose answers look like this, along some range:

  no  no  no  no  YES YES YES YES       ← find the first YES
  ↑ lo               ↑ answer       ↑ hi

"Is nums[i] >= target?" is one such question. So is "can Koko finish with speed k?", "can we ship everything in d days with capacity c?", "is r * r > x?". If the answer for a bigger value is always at least as good, you can binary search the answer itself:

🧩 Template C — binary search on the answer 
def feasible(x):            # O(n) check: does value x work?
    ...

lo, hi = smallest_possible, biggest_possible
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        hi = mid            # works → maybe something smaller works too
    else:
        lo = mid + 1
return lo

Signals: "minimum X such that…", "maximum X such that…", "at least / at most", huge ranges (up to 10⁹) where a loop over every value is too slow.

5. Common mistakes

MistakeFix
Mixing the templates (lo <= hi with hi = mid) → infinite loopTemplate A: <=, mid ± 1. Template B/C: <, hi = mid, lo = mid + 1.
Searching for the last True with lo = midUse mid = (lo + hi + 1) // 2 (round up), or search for the first False and subtract 1.
Binary searching an unsorted listAsk: is there a rule that safely throws away half? If not, sort first or use a dict.
Not testing tiny inputsTrace by hand with 0, 1 and 2 elements — most bugs show up there.

7. 📌 Summary

  • Binary search = halve the search space every step → O(log n).
  • Template A finds an exact value; template B finds the first position where a condition becomes true.
  • Any "no…no YES…YES" question can be binary searched — including the answer itself.
