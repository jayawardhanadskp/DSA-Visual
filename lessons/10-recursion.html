Recursion

A recursive function solves a problem by calling itself on a smaller version of the same problem. It's the key to trees, graphs, backtracking, divide & conquer and dynamic programming — half of this course. Most people find it confusing because they try to follow every call in their head. You'll learn to see the calls first, and then to stop following them.

🎯 After this lesson you can
  • explain the call stack and what "waiting for a return value" means
  • write any recursive function with the 3 questions
  • draw a recursion tree and get the Big-O from it
  • solve factorial, power, flatten, Tower of Hanoi

1. The real-life picture

You're in a cinema queue and want to know your position. You ask the person in front: "what's your position?". They don't know either, so they ask the person in front of them… until the first person says "I'm number 1" (base case). Then the answers come back: "2", "3", … each person adds one. Nobody needed to count the whole queue.

2. 👀 The call stack

Every call gets its own copy of its variables (its own n), stacked on top of the waiting calls. Watch the call stack panel grow on the way down and shrink on the way up, and the call tree on the right: blue = waiting, orange = running, green = finished (with its return value).

It's the same stack as in Flutter When a Flutter exception prints a stack trace, those lines are the call stack: which function called which, newest at the top. Python's limit is about 1000 nested calls — RecursionError: maximum recursion depth exceeded means you probably forgot the base case.

3. The 3 questions (write every recursive function this way)

🧩 Template: recursion 
def solve(problem):
    # 1. BASE CASE: the smallest version I can answer directly
    if problem is tiny:
        return direct_answer
    # 2. SMALLER SUB-PROBLEM: trust that solve() works for it ("leap of faith")
    sub_answer = solve(smaller_problem)
    # 3. COMBINE: build my answer from the sub-answer
    return combine(sub_answer)

Example — sum of a list: (1) the sum of an empty list is 0; (2) the rest of the list is smaller; (3) first item + sum of the rest.

The leap of faith: when you write total(nums[1:]), don't trace it. Assume it returns the right answer for the rest of the list, and only check that your line combines it correctly. This is exactly like using a function from a library — you don't read its code, you trust its contract.

4. 👀 Two calls per call → a tree

When a function calls itself twice, the calls form a tree. Watch fib(5): the dashed grey nodes are calls that haven't happened yet. Notice that fib(3) is computed twice and fib(2) three times.

Each level has up to twice as many calls as the one above → about 2ⁿ calls → O(2ⁿ). fib(40) needs over 300 million calls. In lesson 17 you'll add a small dict that remembers answers, and it becomes O(n). The tree view is how you'll see that.

5. 👀 Halving → only log n calls

If each call makes the problem half as big (and makes only one recursive call), there are only log₂ n calls. 2¹⁰ needs 5 calls instead of 10; 21,000,000 needs 21. This idea — split the problem in half — is the heart of binary search (lesson 12) and merge sort (lesson 11).

6. Big-O of recursion

ShapeExampleTimeSpace (stack depth)
one call, n − 1factorial, sum of listO(n)O(n)
one call, n / 2fast power, binary searchO(log n)O(log n)
two calls, n − 1naive fib, Hanoi, all subsetsO(2ⁿ)O(n)
two calls, n / 2, plus O(n) workmerge sortO(n log n)O(n)

Rule of thumb: time ≈ number of calls × work per call, and space ≈ the deepest the stack gets.

7. Recursion vs loops

Any loop can be written as recursion and the other way round. Use a loop when the problem is a straight line (walk a list). Use recursion when the problem branches or is nested: trees, nested lists, "try every choice". Python has no tail-call optimisation, so very deep recursion (> ~1000) needs a loop or sys.setrecursionlimit.

9. 📌 Summary

  • Every call has its own variables on the call stack; calls wait for the calls they make.
  • Base case + smaller sub-problem + combine. Then trust the recursive call.
  • Draw the call tree: number of calls → time; depth → space.
