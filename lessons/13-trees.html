Trees & binary search trees

You already know trees: a Flutter widget tree! A node has children, the top is the root, nodes without children are leaves. Tree problems are recursion problems in disguise: if you can solve it for one node, given the answers for its subtrees, you can solve it for the whole tree.

🎯 After this lesson you can
  • do DFS (pre/in/post-order) with recursion, and BFS level by level with a queue
  • decide whether information should flow down (arguments) or up (return values)
  • search, insert and validate a binary search tree
  • solve LeetCode 104, 226, 100, 112, 102, 199, 98, 230, 235, 543

  • Binary tree: every node has at most 2 children, left and right.
  • Subtree: a node and everything below it. Every subtree is itself a tree → recursion!
  • Binary search tree (BST): for every node, everything in the left subtree is smaller and everything in the right subtree is bigger.

2. 👀 Depth-first search (DFS)

DFS goes as deep as possible before coming back. With recursion it's 3 lines. The only difference between the three orders is where you handle the node: before the children (pre-order), between them (in-order) or after them (post-order).

🧩 Template: DFS on a tree 
def dfs(node):
    if node is None:          # base case: empty subtree
        return ...
    # pre-order:  use node.val here (top-down)
    left = dfs(node.left)
    # in-order:   use node.val here (BST → sorted order)
    right = dfs(node.right)
    # post-order: use left + right here (bottom-up)
    return ...

Try it: press ✏️ Edit & visualize above and move out.append(node.val) before the first recursive call (pre-order) or after the second (post-order). Watch the order change.

Answers flowing up

"How deep is the tree?" — ask each subtree for its depth, take the bigger one, add 1. Each call returns its answer to its parent.

3. 👀 Breadth-first search (BFS)

BFS visits the tree level by level, using a queue: take a node from the front, add its children to the back. The for _ in range(len(queue)) loop handles exactly one level.

🧩 Template: BFS level by level 
from collections import deque
queue = deque([root])
while queue:
    for _ in range(len(queue)):       # one whole level
        node = queue.popleft()
        ...                           # use node
        if node.left:  queue.append(node.left)
        if node.right: queue.append(node.right)

DFS or BFS? BFS for "level", "closest", "shortest", "right side view". DFS for almost everything else (depth, paths, sums, validate, compare).

4. 👀 Binary search trees

A BST is binary search turned into a tree: at each node go left (smaller) or right (bigger). Search, insert and delete take O(h) where h is the height — O(log n) when the tree is balanced, but O(n) if it grows like a line (insert 1, 2, 3, 4, … to see that).

5. How to think about any tree problem

  1. What does the function return for one subtree? (its depth? its sum? is it valid? the node found?)
  2. Base case: what is the answer for an empty tree (None)? Sometimes also: for a leaf.
  3. Combine: given the answers of the left and right subtrees, what is the answer for this node?
  4. Does something have to flow down instead (a running sum, allowed min/max bounds)? → add parameters.
  5. Is the answer not the return value (e.g. "longest path anywhere")? → keep a best variable outside and update it (nonlocal).

7. 📌 Summary

  • A tree is a node plus subtrees → recursion with base case node is None.
  • DFS (recursion): pre / in / post-order. BFS (queue): level by level.
  • Information flows up (return values) or down (arguments); a global best handles "anywhere in the tree".
  • BST: left < node < right; in-order is sorted; operations are O(height).
