Lesson 04 · Arrays & hashing

Hash maps & sets

If you remember only one data structure for interviews, make it this one. A dict or set answers "have I seen this?" and "how many?" in O(1). It turns a huge number of O(n²) brute-force solutions into O(n).

🎯 After this lesson you can
  • explain how a hash table finds a key without searching
  • use the 4 hashing patterns: seen-before, complement, counting, grouping
  • solve LeetCode 1, 242, 387, 383, 205, 49, 347, 128

1. The real-life picture

A school has 1,000 lockers. Instead of searching every locker for "Kasun's bag", there's a rule: take the name, turn it into a number, and that number is the locker. To find the bag you apply the same rule and open one locker. That rule is the hash function.

  • Two keys can land in the same bucket — a collision. The bucket then holds both, and Python checks the few keys there.
  • Python keeps buckets short by growing the table, so lookups are O(1) on average.
  • That's why keys must be immutable (str, int, tuple): if a key changed, its hash would change and it would be in the wrong bucket.
Dart → Python Map<String, int> → dict, Set<int> → set, map.containsKey(k) → k in d, map[k] ?? 0 → d.get(k, 0), map.putIfAbsent(k, () => []) → d.setdefault(k, []) or defaultdict(list).

2. Pattern 1 — "complement": have I seen what I need?

Two Sum, brute force, checks every pair: O(n²). The hashing idea: walk once, and for each x ask a dict whether its partner target - x already appeared.

3. Pattern 2 — counting

Count everything first, then answer questions about the counts. A dict (or Counter) works for any values; a list of 26 works for lowercase letters (lesson 03).

from collections import Counter
counts = Counter("mississippi")
print(counts)                 # Counter({'i': 4, 's': 4, 'p': 2, 'm': 1})
print(counts["s"], counts["z"])   # missing keys give 0, no KeyError
print(counts.most_common(2))
print(Counter("listen") == Counter("silent"))

4. Pattern 3 — grouping

When things that "belong together" share some key, use a dict from key → list. The art is choosing the key. For anagrams, the key is the sorted letters.

5. Pattern 4 — seen before (sets)

When you only need yes/no, use a set: duplicates (lesson 02), visited cells in a grid (lesson 15), cycle detection, "first repeated…".

🧩 Templates 
# complement / seen-before
seen = {}                          # or set()
for i, x in enumerate(nums):
    if (something about x) in seen:
        return ...
    seen[x] = i

# counting
counts = {}
for x in items:
    counts[x] = counts.get(x, 0) + 1   # or: counts = Counter(items)

# grouping
from collections import defaultdict
groups = defaultdict(list)
for item in items:
    groups[key_of(item)].append(item)

Signals: unsorted input · "pair / two numbers" · "duplicate" · "seen before" · "count / frequency / most common" · "anagram" · "group" · "unique" · need O(1) lookups.

8. 📌 Summary

  • dict/set: add, remove, lookup in O(1) average, at the cost of O(n) memory.
  • Four patterns: complement, counting, grouping, seen-before.
  • Choosing the right key is the creative part (sorted letters, a tuple of counts, a (row, col) pair…).
