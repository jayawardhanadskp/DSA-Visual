Why DSA felt hard — and how this course is different

You tried LeetCode and videos and it didn't click. That is normal, and it is not because you're bad at it. It usually happens for a few specific reasons. This course is built to fix each one.

1. Why videos + LeetCode didn't work

What went wrongWhy it happensWhat this course does instead
"I understood the video, but I can't solve the next problem."Watching is recognising. Solving is producing. Your brain only learns what it actively does.Every idea ends with you typing code that is checked by tests. No passive lessons.
"I don't know how to start."You started problems before learning the ~15 patterns that almost all problems are made of.One pattern per lesson, with a template and the signals that tell you when to use it.
"I can't follow what the code does."You can't yet run code in your head. Videos skip the boring middle steps — but that's where understanding is.A step-by-step visualizer runs the real Python, and you watch every variable change. You also predict the next step and fill trace tables.
"I read the solution and it seemed obvious."Reading a solution feels like learning but isn't (the "illusion of competence").Hints come one at a time. The solution asks you to try 15 minutes first, then asks you to retype it from memory.
"I forgot everything after a week."Memory fades fast without review.Solved problems come back for review after 1, 3, 7, 21 days (see the home page).
"Python feels strange."Your Python basics have gaps, so every problem is two problems.Lesson 01 rebuilds Python for DSA, compared with Dart, which you know.

3. Try the visualizer now

This is the tool you'll use in every lesson. It runs real Python and records every step. Click the box, then press Next ▶ (or the → key) and watch:

  • the yellow line is the line that runs next;
  • on the right, variables that just changed light up;
  • the blue bar under the code explains the step.

Now press 🧠 Predict mode and go again from the start (⏮). Before each step, click the line you think Python runs next. Notice how a for loop jumps back up to line 3 after line 4, and how the call on line 7 jumps into the function.

Then press ✏️ Edit & visualize, change [4, 7, 1] to your own numbers, and run it. (The first time, the browser downloads Python — a few seconds.)

4. The problem-solving routine (use it for EVERY problem)

When you see a new problem, don't start typing. Go through these steps — on paper or as comments in the editor.

🧩 The 6-step routine
  1. Understand. Say the problem in your own words. What is the input? What do I return? What are the limits (size of n)?
  2. Examples by hand. Do 2–3 small examples on paper. Include edge cases: empty list, one element, duplicates, negatives. Watch what your hands do — that is your algorithm.
  3. Brute force first. What is the simplest correct idea, even if slow? Say its Big-O.
  4. Find the waste. What does brute force repeat or check for nothing? Which pattern removes that waste? (Signals in each lesson.)
  5. Code it — write the steps as comments first, then fill in the code.
  6. Test & trace. Run your examples through the code by hand (or with 🎬 Watch my code). Then say the time and space complexity.

Example: the routine on "find the largest number"

  1. Understand: input is a list of numbers (at least one), return the biggest.
  2. By hand: [3, 9, 2, 12, 5]. What did my eyes do? I looked left to right and remembered "the biggest so far": 3 → 9 → 9 → 12 → 12.
  3. Brute force: that is already good: one pass. O(n).
  4. Waste? None — we must look at every number at least once, so O(n) is the best possible.
  5. Code: "biggest so far" becomes a variable best:

"Something so far" variables (best so far, smallest so far, count so far) appear in a huge number of problems. Remember this one.

6. How to study with this course

⏱ Time

60–90 minutes a day, 5–6 days a week. One lesson takes 2–4 days. The whole path is about 10–12 weeks.

📒 Paper

Keep a notebook. Draw the arrays, pointers and trees. Fill trace tables by hand. Drawing is thinking.

🔁 Start each day with reviews

The home page lists the problems due today. Solve them from a blank editor before new material.

🗣 Explain out loud

After each problem, say: "The pattern is ___ because ___. It's O(___)." If you can't say it, you don't know it yet.

💻 Two ways to practise

In the browser (instant tests), or in VS Code with the workbook/ files (python3 workbook/05_two_pointers.py).

🧗 Being stuck is the work

15 minutes stuck = learning. Then use one hint. Then another. The solution is the last step, not the first.

Where you're going Stage 1 fixes Python and teaches Big-O. Stages 2–6 teach one pattern or data structure per lesson. Stage 7 (lesson 20) mixes everything: you get problems without being told the pattern — that is what LeetCode and interviews feel like.
