Sliding window

A sliding window is two pointers that mark the start and end of a section of a list or string. Instead of re-checking every section from scratch (O(n²) or worse), you slide: add what enters on the right, remove what leaves on the left.

🎯 After this lesson you can
  • tell a fixed-size window problem from a variable-size one
  • write both templates from memory and explain why they are O(n)
  • solve LeetCode 643, 1456, 3, 209, 1004, 424, 567, 438

1. The real-life picture

Look at a long train through a window that shows exactly 3 carriages. When the train moves one carriage, you don't recount everything you see — one carriage disappeared on the left, one new carriage appeared on the right. That's it.

2. 👀 Fixed-size window

"Biggest sum of k neighbours." Brute force adds up every group of k numbers: O(n·k). The window keeps a running sum and updates it in O(1) per slide. The purple cells are the current window.

🧩 Template: fixed window of size k 
window = sum(nums[:k])          # (or counts of the first k items)
best = window
for right in range(k, len(nums)):
    window += nums[right]       # add the new element
    window -= nums[right - k]   # remove the element that left
    best = max(best, window)

Signals: "subarray / substring of length k", "every window of size k", "average of k consecutive".

3. 👀 Variable-size window

Now the size is not given: "the longest substring with no repeated characters". The window grows to the right one step at a time. When it becomes invalid (a repeated character), it shrinks from the left until it is valid again.

The other kind: "the shortest section whose sum is at least 7". Here the window shrinks while it is valid (to find a shorter valid one).

🧩 Template: variable window 
left = 0
state = ...                         # sum, counts, set of what's inside
best = ...
for right in range(len(s)):
    add s[right] to state           # 1. grow
    while window is INVALID:        # 2. shrink until valid
        remove s[left] from state   #    (for "shortest": while VALID → record, then shrink)
        left += 1
    best = max(best, right - left + 1)   # 3. record
return best

Signals: "longest / shortest / minimum / maximum contiguous subarray / substring", "with at most k …", "without repeating", "sum ≥ target" (positive numbers).

Why O(n)?

There's a while inside a for, which looks like O(n²). But count the moves: right moves n times in total and left also moves at most n times in total — it never moves back. So all the work together is at most 2n steps → O(n). This "count the total pointer moves" argument is called amortised analysis, and you can use it in interviews.

4. How to design the window — 3 questions

  1. What is the state I need to know about the window? (a sum, a count of zeros, a set of characters, letter counts)
  2. When is the window invalid? (repeated char, more than k zeros, too many letters to replace…)
  3. When do I record the answer — after shrinking (longest) or during shrinking (shortest)?

Example, "max consecutive ones if you can flip k zeros": the state is number of zeros in the window; it's invalid when zeros > k; record the length after shrinking. The problem never mentions a window — you rephrase it into one. That rephrasing is the skill.

5. Common mistakes

MistakeFix
Window length right - leftIt's right - left + 1 (both ends included).
Using if instead of while to shrinkSometimes you must remove several elements. Use while.
Forgetting to undo the state when shrinkingWhatever you add for right, you must remove for left.
Using a window with negative numbers for "sum = k"Use prefix sums + dict (next lesson).

7. 📌 Summary

  • Window = a contiguous section marked by left and right.
  • Fixed size: add one, remove one. Variable size: grow, shrink while invalid (or while valid for "shortest"), record.
  • Always O(n) because both pointers only move forward.
