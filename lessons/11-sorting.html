Sorting

In real code you call sorted(). But knowing how sorting works teaches the two big strategies of algorithms — "grow a sorted part step by step" and "divide & conquer" — and "sort first" is the hidden first step of countless problems.

🎯 After this lesson you can
  • explain insertion sort, merge sort and quick sort, and their Big-O
  • use sorted / .sort with key=, tuple keys and reverse=
  • recognise when sorting first makes a problem easy

2. 👀 Insertion sort — O(n²)

Like sorting playing cards in your hand: pick up the next card and slide it left until it's in the right place. The green part is always sorted.

  • Worst case (reversed list): every card slides all the way → about n²/2 steps → O(n²).
  • Almost sorted list: every card slides 0–1 places → O(n). Great for small or nearly sorted data.
  • In place: O(1) extra memory. Stable: equal values keep their order.

(Bubble sort and selection sort are the other famous O(n²) sorts. You can see bubble sort in the race above; it's mostly useful as a bad example.)

3. 👀 Merge sort — O(n log n)

Divide & conquer: split the list in half, sort each half (recursion — trust it!), then merge the two sorted halves with two pointers. Watch the call tree: the splitting goes down log₂ n levels, and each level merges n elements in total.

level 0:  [6, 3, 8, 1, 5, 2]                 1 list of 6
level 1:  [6, 3, 8]   [1, 5, 2]              2 lists of 3
level 2:  [6] [3, 8]  [1] [5, 2]             ...
level 3:      [3] [8]     [5] [2]            log₂(6) ≈ 3 levels × n work each = O(n log n)

Merge sort is always O(n log n), and stable, but needs O(n) extra memory for the merged lists.

4. 👀 Quick sort — O(n log n) on average

Pick a pivot. Partition: move everything smaller than the pivot to its left, then put the pivot right after them — it is now in its final place forever. Then quick-sort the left part and the right part.

  • Average O(n log n), in place (O(log n) stack). Usually the fastest in practice.
  • Worst case O(n²): when the pivot is always the smallest or biggest (e.g. sorted input with the last element as pivot). A random pivot avoids this.
  • The partition idea alone solves problems: "sort colors", "k-th largest" (quickselect), "move zeroes".

5. Sorting in real Python

Python uses Timsort (merge sort + insertion sort for small runs): O(n log n) worst case, O(n) on sorted data, and stable.

nums = [5, 2, 9, 1]
print(sorted(nums), nums)          # sorted() returns a NEW list
nums.sort(reverse=True)            # .sort() changes the list, returns None
print(nums)

words = ["kiwi", "Fig", "banana", "apple"]
print(sorted(words))                       # 'F' < 'a' (uppercase first!)
print(sorted(words, key=str.lower))        # case-insensitive
print(sorted(words, key=len))              # by length (stable: ties keep order)
people = [("ann", 30), ("bob", 25), ("cat", 30)]
print(sorted(people, key=lambda p: (-p[1], p[0])))   # age desc, then name asc
print(max(people, key=lambda p: p[1]))     # key= works for max/min too
Dart → Python Dart: list.sort((a, b) => a.age.compareTo(b.age)) (a compare function). Python prefers a key: list.sort(key=lambda p: p.age). If you really need a compare function, use functools.cmp_to_key (practice problem 8).

6. "Sort first" — the hidden pattern

Ask early: would this be easy if the input were sorted? Sorting costs O(n log n), which is usually fine.

9. 📌 Summary

  • Insertion sort: simple, O(n²), great for small/almost sorted data.
  • Merge sort and quick sort: divide & conquer, O(n log n).
  • In Python: sorted(…, key=…, reverse=…). Tuple keys for several criteria; negate for descending numbers.
  • "Sort first" unlocks two pointers, binary search, greedy and interval sweeps.
